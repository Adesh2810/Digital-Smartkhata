6. Interview Questions And Answers

Q1. Tell me about your SmartKhata project.

SmartKhata ek full-stack business management application hai jo small retailers ke credit ledger, payment recovery, customer records, suppliers, inventory, shopping orders aur staff management ko handle karta hai. Isme React frontend, Express backend aur MySQL database use hua hai. Main isme frontend screens, API integration, backend REST APIs, database queries, validations aur balance/stock calculation logic par kaam karta hu.

Q2. What was your role in the project?

Mera role full-stack developer ka tha. Frontend mein React pages, forms, dashboard, filters, reusable services aur API integration kiya. Backend mein Express routes/controllers, MySQL CRUD, authentication, payment transaction handling, inventory stock update aur staff attendance APIs implement kiye.

Q3. Why did you choose React for frontend?

React component-based hai, isliye large UI ko pages/components mein divide karna easy hota hai. SmartKhata mein multiple modules hain, jaise Dashboard, Customers, Staff, Payment, Inventory, so React state management, conditional rendering aur reusable components useful rahe.

Q4. How frontend communicates with backend?

Frontend Axios ke through backend REST APIs call karta hai. Example: customerService.js customers API call karta hai, paymentService.js payments API call karta hai, staffService.js staff APIs call karta hai. Base URL mostly http://localhost:5000/api hai.

Q5. Explain your backend architecture.

Backend Node.js Express par based hai. server.js mein middleware aur routes register hain. Har module ka route file hai, jaise customerRoutes, paymentRoutes, staffRoutes. Business logic controllers mein hai. Database connection config/db.js mein mysql2 se createConnection ke through hota hai.

Q6. Which database did you use and why?

MySQL use kiya because project mein structured relational data hai: customers, payments, orders, order items, products, suppliers and staff. In tables ke beech relations aur reporting queries ke liye SQL suitable hai.

Q7. How did you handle payment and customer balance?

Payment add karte time backend customer ko SELECT ... FOR UPDATE se lock karta hai, previous_balance read karta hai, payment amount minus karke current_balance calculate karta hai, payment row insert karta hai aur customers table update karta hai. Ye operation MySQL transaction ke andar hota hai, so data consistency maintain hoti hai.

Q8. Why did you use database transactions?

Payment aur order flow mein multiple database operations ek saath hote hain. Agar payment insert ho gaya but customer balance update fail hua to data mismatch hoga. Transaction se either all operations commit hote hain ya failure par rollback hota hai.

Q9. How does inventory stock update work?

Products table mein stock_qty maintain hota hai. Product update ke time old stock aur new stock ka difference calculate karke stock_movements mein ADD/REDUCE record insert hota hai. Order create hone par product stock reduce hota hai, aur order cancel hone par stock restore hota hai.

Q10. What is the order flow?

User shopping order create karta hai with customer name, mobile, pickup time and selected products. Backend product stock validate karta hai, shopping_orders mein order create karta hai, shopping_order_items insert karta hai, stock reduce karta hai and stock_movements mein ORDER entry add karta hai.

Q11. How did you implement authentication?

Register API user data validate karti hai, duplicate email check karti hai, password bcrypt se hash karti hai aur DB mein save karti hai. Login API email se user fetch karti hai, bcrypt.compare se password verify karti hai and JWT token generate karti hai.

Q12. What validations did you add?

Frontend par required fields, mobile number, email, salary, positive amount validations hain. Backend par amount greater than 0, valid date format, valid IDs, stock availability, paid amount cannot exceed total amount, customer/staff/product existence checks hain.

Q13. Explain Staff module.

Staff module HRMS style hai. Isme staff registration, list, search, department/status filters, profile view, attendance entry, attendance history, salary dashboard, salary payment/advance backend APIs and report/export action buttons hain. Backend staff, staff_attendance, staff_salary_payments and staff_advances tables use karta hai.

Q14. What is the Dashboard doing?

Dashboard multiple APIs se data fetch karta hai: customers, credits, payments, orders and inventory products. Ye total customers, total credit, total payment, pending balance, recent transactions, top products, low stock alerts and chart display karta hai.

Q15. How did you handle API errors?

Backend controllers mein sendError helper use kiya gaya hai jisse consistent JSON response milta hai: success false and message. Frontend mein try/catch se error message display kiya jata hai, for example staff save failed ya backend/database check message.

Q16. What is the difference between PUT, POST, DELETE and GET in your project?

GET data fetch ke liye, POST new record create ke liye, PUT existing record update ke liye, DELETE record remove ke liye use hua. Example: POST /api/staff adds staff, PUT /api/staff/:id updates staff, DELETE /api/staff/:id deletes staff, GET /api/staff fetches staff.

Q17. How did you design reusable services?

Frontend mein API logic service files mein separate kiya. Components directly Axios URL hardcode na karein, isliye customerService, paymentService, staffService, shoppingService, inventoryService use kiye. Isse code maintainable hota hai.

Q18. How do you protect against SQL injection?

Most queries parameterized placeholders ? ke through run hoti hain, jisme values array mein pass hoti hain. Is approach se user input directly SQL string mein concatenate nahi hota, so SQL injection risk reduce hota hai.

Q19. What challenges did you face?

Main challenge balance and stock consistency tha. Payment add/update/delete ke time customer balance correctly maintain karna aur order cancel/reopen ke time stock restore/reduce karna important tha. Iske liye transactions, row locking, validations and stock_movements table use kiya.

Q20. What improvements are pending?

Reports page and Settings page abhi placeholder stage mein hain. Transactions unified ledger API fully active nahi hai. Auth middleware and ProtectedRoute ko consistently apply karna hai. DB credentials ko .env mein move karna hai. Automated tests add karne hain.

Q21. How would you improve this project for production?

DB credentials .env mein rakhunga, JWT secret environment variable se read karunga, protected routes apply karunga, input validation library like Joi/Zod use karunga, automated API tests add karunga, proper migrations create karunga, logging and deployment setup karunga.

Q22. What is bcrypt and why did you use it?

bcrypt password hashing library hai. Plain password database mein store karna unsafe hota hai. Register ke time password hash hota hai and login ke time entered password hash se compare hota hai.

Q23. What is JWT?

JWT ek token-based authentication mechanism hai. Login success hone ke baad backend token generate karta hai. Frontend token store karke protected APIs ke liye Authorization header mein bhej sakta hai.

Q24. What is useEffect used for in your React pages?

useEffect data load karne ke liye use hota hai when page/component mounts. Example Dashboard load hote hi customers, payments, orders, products APIs call karta hai. Staff page load hote hi staff summary and staff list fetch karta hai.

Q25. What is useMemo used for?

useMemo expensive derived calculations avoid karne ke liye use hota hai. Dashboard mein totals, filtered transactions, top products and low stock data derive hota hai. Staff page mein filtered/sorted staff list useMemo se calculate hoti hai.

Q26. Explain customer history feature.

Customer history payments, customer product entries aur shopping order items ko combine karta hai. Backend separate queries run karke common format mein data map karta hai and date descending order mein return karta hai.

Q27. How do you calculate pending amount in product entry?

Product entry mein total_amount = price * quantity hota hai. pending_amount = total_amount - paid_amount hota hai. Agar paid_amount total se zyada ho to backend validation error return karta hai.

Q28. How supplier purchase module works?

Supplier purchase mein supplier_name, purchase_from, amount, paid_amount, bill_no, purchase_date, product_details and note save hote hain. pending_amount query mein amount - paid_amount se calculate hota hai. Summary total debit, paid and pending return karti hai.

Q29. What is your strongest contribution?

Mera strongest contribution payment/balance and inventory/order flow hai, kyunki isme business-critical calculations hain. Maine API validation, transaction handling, current_balance update, stock deduction/restore and history tracking jaise logic par kaam kiya.

Main React frontend, Node Express APIs, MySQL queries, CRUD operations, form validations, API integration and debugging mein comfortable hu. Main abhi complex architecture design independently seekh raha hu, but module-level development and issue fixing confidently handle karta hu.”
